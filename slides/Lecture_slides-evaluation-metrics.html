Categories first.

The Confusion Matrix

Four Ways To Be Right Or Wrong

Every prediction a classifier makes lands in exactly one of four quarters.

Rows are the truth · columns are the prediction
predicted ordinarypredicted good
actually ordinaryTN — True NegativeFP — False Positive
actually goodFN — False NegativeTP — True Positive
from sklearn.metrics import confusion_matrix
from sklearn.linear_model import LogisticRegression

model = LogisticRegression(max_iter=1000) # classifier. We cover this on Monday
model.fit(X_train, y_train)               # 3,673 training bottles
y_pred = model.predict(X_test)            # 1,225 held-out bottles
print(confusion_matrix(y_test, y_pred))

# [[912,  48],   · 912 ordinary wines called ordinary, 48 called good
# [188,  77]]    · 188 good wines MISSED, 77 good ones found
  • sklearn orders the confusion matrix as [[TN, FP], [FN, TP]] — truth down the side, prediction across the top.
  • The mistake everyone makes once: reading it transposed. Most textbooks, and plenty of blog posts, draw it the other way round — prediction down the side, truth across the top.
  • Read it mirrored and the 48 false positives become 48 false negatives. Precision and recall then swap places, and every conclusion you draw from them is backwards.
  • So check one cell you can reason about before trusting the other three. Most wines are ordinary and the model mostly says ordinary, so the largest count has to sit top-left: 912 confirms that the rows really are the truth.
  • FN = 188. The model missed 188 of the 265 good wines in the test set = 71%.

Four numbers — let’s see how we can use them.

Accuracy

80.7% Accurate Can Be Deceiving

Accuracy is the obvious metric for every prediction. How accurate is our model — how many did we get right?

Accuracy = (TP + TN) / (TP + FP + TN + FN)

TP true positive · TN true negative · FP false positive · FN false negative

from sklearn.metrics import accuracy_score

accuracy_score(y_test, y_pred)   # 0.807 strong start!
  • 80.7% correct. Would you use it?

Now fit the dumbest model that could possibly work.

from sklearn.dummy import DummyClassifier

baseline = DummyClassifier(strategy="most_frequent")   # always says "ordinary" wine
baseline.fit(X_train, y_train)
baseline.score(X_test, y_test)   # 0.784 - it never looks at the features
  • A model that ignores every feature scores 0.784. Ours scores 0.807.
  • All that work bought 2.3 percentage points. This is the accuracy paradox: when one class dominates, accuracy mostly measures the class imbalance.
  • Fit a baseline model first. A score means nothing until you know what you could get for free.

The model found only 77 of the 265 good wines — we need a different metric that captures this.

Recall

How Many Good Wines Did We Catch?

Recall ignores the majority class entirely. It asks: “of everything that was labelled good, what fraction did we find?”

Recall = TP / (TP + FN)

TP true positive · FN false negative — the positives we missed

from sklearn.metrics import recall_score

recall_score(y_test, y_pred)   # 0.291 - 77 found / 265 actually good
  • Accuracy said 0.807. Recall says 0.291. Same model, same predictions, different perspectives.
  • The model missed 71% of the good bottles. Accuracy never showed you that, because it was drowned out by the majority “ordinary” wine class.
  • Recall is also called sensitivity, or the true positive rate.

Recall is easy to trick, though: label every bottle good and recall hits 1.0. We need the other side of the story.

Precision

When We Said Good, Were We Right?

Precision looks only at the predictions you act on. Of every wine flagged good, what fraction really was?

Precision = TP / (TP + FP)

TP true positive · FP false positive — the false alarms

from sklearn.metrics import precision_score

precision_score(y_test, y_pred)   # 0.616 - 77 correct / 125 flagged good
  • The model flagged 125 bottles. 77 were genuinely good, 48 were not.
  • Recall counts what you missed (FN). Precision counts what you falsely raised (FP).

Which mistake is more costly? Which metric is better suited?

  • Cancer screening — miss a tumour, or scare a healthy patient?
  • Spam filter — let junk emails through, or bin a real invoice?

You can trade one for the other without refitting your model.

The Threshold Dial

Dial in on Your Preferences

A classifier does not output a class. It outputs a probability, and a threshold turns that probability into a “yes” or a “no” — typically at 0.50.

Anything above the threshold is classified as “yes”; anything below is classified as “no”.

proba = model.predict_proba(X_test)[:, 1]   # column 1 = P(good)
y_pred_050 = (proba >= 0.50).astype(int)    # the default
y_pred_030 = (proba >= 0.30).astype(int)    # more willing to say the wine is "good"

Every threshold from 0.05 to 0.75 on the 1,225 test bottles. Orange = precision | Blue = recall.

The same model, two thresholds — nothing was refitted
thresholdprecisionrecallF1
0.500.6160.2910.395
0.300.5230.6540.584
  • The closer the score is to 1, the better. Dropping the threshold to 0.30 lifts recall from 0.291 to 0.654, but it costs precision: 0.616 down to 0.523.
  • The curves cross over at 0.36. There is no setting where both are high; that is the trade-off, not a bug.

0.50 is a default threshold, not a law. Pick it from which mistake costs you more.

F1-score

One Number That Balances Precision and Recall

When you must rank models on a single score but refuse to ignore either error, combine them.

F1 = 2 · (Precision · Recall) / (Precision + Recall)

Precision fraction of flagged positives that were right · Recall fraction of real positives that were found

from sklearn.metrics import f1_score

f1_score(y_test, y_pred)   # 0.395 - at the default 0.50 threshold
  • F1 is the harmonic mean, not the ordinary mean. The plain mean of 0.616 and 0.291 would be 0.454.
  • The harmonic mean is dragged toward the smaller of the two values, so one terrible score cannot be outweighed by an excellent one.
  • Precision = 1.0 and Recall = 0.0 makes F1 = 0.0. Exactly the behaviour you want from a summary of the two metrics.

F1 judges one threshold. Next, we judge every threshold at once…

ROC and AUC

Receiver Operating Characteristic (ROC) Curve

Sweeping the thresholds from 0 to 1, plot the false positive rate against recall and you get a ROC curve.

FPR = FP / (FP + TN)

FPR — false positive rate: the share of ordinary wines wrongly flagged as good

from sklearn.metrics import roc_curve, roc_auc_score

proba = model.predict_proba(X_test)[:, 1]            # P(good)
fpr, recall, thresholds = roc_curve(y_test, proba)
roc_auc_score(y_test, proba)                         # 0.784
  • A common mistake to avoid: passing y_pred instead of proba, because the ROC curve requires probability scores, not binary predictions.
  • The dashed diagonal is the “no skill” baseline — 0.5 is the score you get by guessing at random. AUC is the area under your curve: 1.0 is a perfect score.
  • An AUC of 0.784: pick one “good” and one “ordinary” bottle of wine at random, and the model scores the good one higher 78.4% of the time.

0.784 looks respectable, but we need to be cautious about interpreting this metric on imbalanced data.

Imbalanced Classes

All data scientists find imbalanced datasets challenging

So they use an accuracy metric that considers both classes. Only 21.6% of the wine bottles are good. Two tools stop the majority class flattering the score.

Balanced accuracy = (Recall(-ve) + Recall(+ve)) / 2

Recall(+ve) — recall on the positive class · Recall(-ve) — recall on the negative class · each class counts equally, whatever its size

from sklearn.metrics import accuracy_score, balanced_accuracy_score

accuracy_score(y_test, y_pred)            # 0.807
balanced_accuracy_score(y_test, y_pred)   # 0.620

# The dummy classifier that always predicts the majority class scores 0.500
  • The drop from 0.807 → 0.620 is the overestimated accuracy that was given to the model.

We can now plot the precision-recall curve:

  • ROC’s “no skill” line is the diagonal, and it uses the FPR. The precision-recall “no skill” line is the positive rate = the number of positive instances / total instances (0.216).
  • The FPR divides by 3,838 ordinary wines, so a few hundred false positives barely move it. ROC overestimates a model whenever the negative class is disproportionately larger. Precision divides by what was actually flagged, and cannot hide them.

Imbalanced data? Rare positives? Read the precision-recall curve.

Let’s add to our regression metrics

MAE, MSE, and RMSE

Let’s try to predict the alcohol content of a wine. Same 4,898 bottles, new target: alcohol, a number from 8.0 to 14.0 % ABV.

Nothing is right or wrong any more — only near or far (in terms of error). So we measure the size of the miss.

MAE = (1/n) · Σ |yᵢ − ŷᵢ|

n number of observations · yᵢ actual value · ŷᵢ predicted value

MSE = (1/n) · Σ (yᵢ − ŷᵢ)²    RMSE = √MSE

the square punishes a big miss far harder than two small ones · the root puts the answer back into target units (% ABV)

from sklearn.metrics import mean_absolute_error, root_mean_squared_error

mean_absolute_error(y_test, y_pred)       # 0.292 % ABV  · the typical miss
root_mean_squared_error(y_test, y_pred)   # 0.382 % ABV  · bigger. always.
  • MAE rises steadily, in an almost straight line; RMSE takes off.
  • So RMSE > MAE, always. But an RMSE that dwarfs MAE diagnoses unevenly distributed errors: your predictions suffer from a few massive outliers rather than small, uniform misses. Here, 0.382 against 0.292 implies a minority of bottles are badly mispredicted.

Add this to what you learned on Monday.

R²

Compared To Just Guessing The Mean

An error of 0.292 % ABV means nothing until you know what a thoughtless model would score.

R² = 1 − (SSres / SStot)

SSres sum of squared residuals, Σ (yᵢ − ŷᵢ)² · SStot total sum of squares, Σ (yᵢ − ȳ)² where ȳ is the mean

from sklearn.metrics import r2_score

r2_score(y_test, y_pred)   # 0.904
# DummyRegressor(strategy="mean") scores -0.0 here, by construction
  • R² is the variance the model explains that the mean does not. 0.904 is a seemingly good fit, but it needs adjusting.
  • Always-guessing-the-mean scores 0.0 — not by luck, by definition. That is why DummyRegressor is the free baseline here.
  • R² can go negative. That means the model did worse than the mean, and it is a real thing to see on test data. Any result is a good result.

Nine metrics, too many to choose from… so when do we use each one?

Choosing a Metric

There Is No Best Metric

The right metric depends on your specific problem and the costs of different types of errors.

Read the left column as a sentence about your problem
When…reach forbecause…
missing a positive is expensiverecallScreening mammograms: a missed tumour costs a life, a false alarm costs one more scan. Recall counts the misses.
a false alarm is expensiveprecisionA spam filter: junk in the inbox is a nuisance, a client’s invoice in the spam folder is a lost contract. Precision counts the mistake.
you need one number, both matterF1Ranking five fraud models: A missed fraud and a frozen card both cost money, and F1 refuses to let a model win on one while failing the other.
comparing models, threshold not yet fixedROC AUCChoosing a churn model before marketing has decided how many customers it can afford to call. AUC scores the ranking at every threshold, so the choice survives that decision.
positives are rareprecision-recall curve, balanced accuracyCard fraud at 2 cases in 1,000: FPR divides by the huge negative class, so ROC looks superb whatever you do. Precision divides by what you flagged and cannot.
predicting a number, important outliersRMSEForecasting electricity demand: one badly missed peak day blacks out a grid, and squaring the error is what makes the metric say so.
number prediction, unimportant outliersMAEPredicting a delivery time in minutes: 20 minutes out is exactly twice as annoying as 10, so the plain average miss is the honest number.

Two more regression metrics worth knowing and some tricks:

from sklearn.metrics import mean_absolute_percentage_error, median_absolute_error

mean_absolute_percentage_error(y_test, y_pred)  # 0.028  · MAPE: 2.8% off, unit-free
median_absolute_error(y_test, y_pred)           # 0.243  · vs MAE 0.292
  • MAPE is a percentage, so it compares across targets on different scales. It explodes if any actual value is near zero.
  • Median absolute error ignores outliers completely. 0.243 < 0.292 is the same warning RMSE conveys — a few rows are badly wrong.
  • When the numbers disagree, plot the residuals with PredictionErrorDisplay and go look at the rows that failed.

Want everything? use classification_report or regression_metrics. But! Always pick the metric before you fit a model. Why?

Consider This

Six Situations, Six Different Answers

Every one of these is a real machine learning problem, and every one needs a different metric.

Call out the metric you would put in front of the person paying for the model — and say what it would cost to get it wrong.

  • Hiring. A CV screener is 95% accurate, and 4% of applicants in the training dataset are qualified. What would “reject everyone” score? Which metric, and who pays for a false negative — the company, or the applicant who never hears back?
  • Intensive care. A model flags patients developing sepsis. A miss can be fatal; a false alarm costs one more blood test. Which metric?
  • Card fraud. A bank auto-blocks transactions it thinks are stolen. Two in a thousand really are, and a wrongly blocked card loses a customer. Which metric, and which of the two curves?
  • Churn. Two models, and marketing has not yet decided how many customers it can afford to target. Which metric lets you pick a model before the threshold is chosen?
  • House prices. A handful of mansions cost twenty times the median. Which metric and does your answer change if those mansions are the clients paying for the model?
  • Delivery times. The app predicts arrival in minutes, and being 20 minutes out is exactly twice as annoying as 10. Which metric?

Somebody chose the metric on every dashboard you will ever be shown. Choosing it is a decision about people, not statistics.

Glossary

Look It Up

Classification — a task whose target is a category, so a prediction is simply right or wrong.

Regression — a task whose target is a number, so a prediction is near or far and the size of the miss is what we measure.

Positive class — the outcome you are trying to detect. Naming it is a modelling choice, and it decides what TP, FP and FN mean.

Class imbalance — one class far outnumbering the other, so a model can score well by ignoring the rare one.

Confusion matrix — the 2×2 table of TP, FP, TN, FN. In scikit-learn the truth runs down the side and the prediction across the top.

True positive (TP) — predicted positive, and it really was positive. A catch.

False positive (FP) — predicted positive, actually negative. A false alarm.

True negative (TN) — predicted negative, and it really was negative. A correct all-clear.

False negative (FN) — predicted negative, actually positive. A miss.

Accuracy — of all predictions, the share that were right.

Accuracy paradox — when one class dominates, accuracy mostly measures the class balance rather than the model.

Baseline — the dumbest defensible model, fitted first, so a score has something to beat.

Recall — of the real positives, the share found. Also called sensitivity, or the true positive rate.

Precision — of everything flagged positive, the share that really was.

Decision threshold — the probability cut-off, 0.50 by default, that turns a predicted score into a predicted class.

F1-score — the harmonic mean of precision and recall.

Harmonic mean — an average pulled toward the smaller value, so one weak half cannot hide behind a strong one.

ROC curve — recall against false positive rate, traced across every threshold.

False positive rate (FPR) — of the real negatives, the share wrongly flagged positive.

ROC AUC — area under the ROC curve. 0.5 is guessing, 1.0 is perfect.

Balanced accuracy — the mean of the per-class recalls, so each class counts equally whatever its size.

Precision-recall curve — precision against recall; the honest curve when positives are rare.

Positive rate — the share of all observations that are positive. It is the no-skill line of a precision-recall curve.

MAE — mean absolute error, the typical miss, in the target’s own units.

MSE — mean squared error; squares the miss, so big errors dominate.

RMSE — the root of MSE, back in the target’s units. Always at least MAE.

R² — the share of variance explained versus always guessing the mean. 0 is the mean, negative is worse.

MAPE — mean absolute percentage error; unit-free, but unstable when any actual value is near zero.

Median absolute error — the middle miss; ignores outliers entirely.
